# 实际导出、发布包与可恢复整理

## 完成与检查分别记

“工程可渲染”“已导出”“已做技术检查”“实际视觉抽播”“主观耳听”“用户接受”“已发布”是不同事实。每条证据带实际文件标识和修订号，不用上一版同名JPG／报告替新版本背书。若最终只改封装且画面／音频等价，证明准确等价范围后引用原观察，不能冒称重新看／听一轮。

做过什么就记录什么：播放器、倍速、显示尺寸、实际起止窗口、具体观察、是否耳听、未覆盖部分。浏览器播放进度、ASR、波形、静帧、包hash、PTS和完整解码都不能替代观看或耳听。没有听力能力时明说限制，用户接受也不反推助手曾完成听审。

## 实际成片检查矩阵

先内部短片检查新布局、镜头与关键动作，随后继续完整文件。新片／完整剪辑应对实际导出做：

| 范围 | 必查内容 |
| --- | --- |
| 0–3秒直到第一完整观点 | 首帧、第一声、核心真实钩子已懂、问答对象、接入背景是否自然 |
| 每个新剪口与跨源接缝 | 句头尾音、条件／互动、音画同cut、口型与手势连续，无假反应 |
| 镜头进入／停稳／退出 | 明显程度、语义锚点、接话者、脸与手安全、回全景 |
| 身份到产品 | 宽景停稳、姓名＋简介静止可读、整组退尽、独立Header／Logo，无人名变Logo |
| 图解与信息交接 | 正确时机入场、固定主锚、分支不穿字、最后关系完成后读时、回现场与必要提示 |
| 每个修改过的强调及代表性字幕 | 普通态、放大中、完成态、整句末帧、下一句、真词同步、邻字让位、seek一致 |
| 趣味效果与SFX | 真实互动锚点、进退因果、脸／字幕不遮、声音弱于话且不吞词 |
| 总结、预告与末尾 | 谁推荐什么及限定完整，读完才交接，无抢屏／截字／空白断尾 |

正常速度与手机尺寸都实际观看。全部强调可自动取状态帧辅助筛查，关键运动须播放；自动逐窗播放的范围也不等于人逐秒全看。适合时让独立复核者直接看实际输出并报告窗口，不把预期答案当观察结果。无法完成某项主观检查时保留真实限制，并完成可执行技术检查和已授权交付。

技术检查包括：媒体可解码、帧率／帧数／时长、音频样本与容器时基、EDL无洞无叠、当前字幕和章节、源依赖与hash。分段组装还须验证真实可独立解码接点、编码参数一致、PTS/DTS连续、尾部无丢帧；使用全重编码还是包复制属于实现选择，不将某次“包相同”泛化到新片。

## 发布包：完整制作的默认终点

完整制作不在MP4处结束；默认同时备齐下列材料，无需再问用户是否需要封面或文案。用户明确只要局部返修、样片或某单张时按当期范围，不扩大制作。

| 材料 | 完成条件 |
| --- | --- |
| 当前成片 | 完整可播放，真实原声与最终时钟一致，实际完成所列检查 |
| 三比例封面 | 使用用户已选[中央漫画分格配方](comic-panel-cover.md)；3:4、4:3、16:9分别构图，原图和手机尺寸实际查看 |
| 三种SRT | 中文、英文、中英双语共用最终字幕编号与时码；保留原话条件，英语不得新增承诺或嘉宾发言 |
| 四平台文案 | 抖音、小红书、视频号、B站各有可复制标题、正文／简介、话题和适用来源／制作说明，不只列四个平台名字 |
| 当前成片章节 | 长片默认每行HH:MM:SS＋标题，定位当前输出，不是原录制时码；删段或变速后一并更新 |
| 使用说明与ZIP | 平台→成片／封面／文案映射，真实内嵌字幕状态，逐文件检查归档与交付目录一致；不混原片、源码、缓存或过期候选 |

四平台具体便利格式与用途映射可调用[真人口播四平台交付](../../edit-talking-head-social-video/references/four-platform-delivery.md)。同一成片兼容四个平台时共用一份，不复制四份来凑数；平台确有不同规格时才另导出。说明字幕是否已内嵌，避免用户又叠加同语种SRT；保护已确认成片，不为发布包无声改动其字幕或重编码。

封面的已选默认、身份、文案、Logo、自然字形、信息分布、三比例与实看门槛统一由[中央漫画封面参考](comic-panel-cover.md)维护。泛用封面Skill只提供公共制作和检查能力，不能把本Skill的明确选版改回电影海报或其他默认。只有用户另选方向时才切换；已选当前封面按明确保护范围沿用。

封面、平台标题和开头真实钩子承诺同一件片中可兑现的事。价格、额度、功能与模型体验若来自录制时个人讨论，不写成最新官方保证。文案来源与制作说明按实际素材/工具表达，不把真人实拍说成AI合成视频，亦不把生成插画称为原片摄影。没有平台结果时不编帖子链接、BV号或已发布状态。

已生成、实际看过、主观听审、用户接受、上传／投稿与发布是不同状态。完整材料核对后直接交可用文件与链接，不重复请求日常制作批准；未经当次明确授权不自动上传、发布或联系嘉宾／品牌。

## 留一个能重建的项目

保留当前接受交付、一套规范可编辑源、用户原片、必要输入、实际字体／Logo／库、共用身份与时钟、重要用户反馈、精剪取舍和紧凑有效证据。规范源应能完整重建，不依赖被回收的工作缓存或旧分支。未来导出写规范目的地，修导航、链接、清单与打包脚本。

新候选尚在比较或待审时保留；“再试一个”不是拒绝。用户拒绝某试验或验证后选定替代时，检查引用、软链／硬链接及依赖，确认旧输出、旧源、旧音频、独占派生、冗余包、调试输出、抽检帧和空任务目录已无用途，再按确切归属可恢复移入唯一系统Trash目录，保留相对路径。不要为无用历史留下v1/v2/v3档案，也不要删除原片、共享缓存、运行依赖、配置、凭据、VCS或外部发布副本。

必要旧证据先提取保留再移动其余。使用项目已有整理记录更新恢复映射，避免另建一叠dated报告。Trash不可用则保留并说明整理未完成，不能改成永久删除。移动后重列保留树，验证源依赖和交付；应字节不变的媒体比较hash，不为声称验证重渲未变媒体。交付归档内容改变时重建归档，并核对其与保留文件一致；回复前重新确认恢复路径可用。
